# 截图与贴图（capture）

## 功能

- 选区、窗口、全屏三种入口；支持多显示器与跨屏选区。
  悬停自动框住鼠标下的 UI 元素（按钮/输入框/图标/文本区），单击即取该元素，
  气泡上可直接「复制文本」/「复制信息」/「存图标」。
- 标注：矩形、椭圆、箭头、画笔、马赛克、文字、序号、高亮、裁剪。
- 美化：背景、圆角、边框、阴影、水印、内边距，实时预览。
- 拼接：多张截图按横/纵/网格拼接。
- 长截图：选区内滚动，按行特征对齐后拼接。
- OCR：默认用系统自带 `Windows.Media.Ocr`，不联网、不下载模型；可选装 PaddleOCR 模型（约 15 MB，
  设置页「截图工具 → OCR 增强」里点「下载模型」，中文/小字/表格更准，出错自动回退系统 OCR）。
- 贴图：截图钉在桌面最上层，滚轮缩放、双击关闭。
- 输出：PNG 写盘 + 剪贴板（PNG 与 DIB 双格式）。

## 交互流程

```text
热键 / 托盘 / 工具条
  → 抓取虚拟桌面（一次 BitBlt 到 32bpp DIB）
  → 全屏分层覆盖层：变暗、选区、放大镜、元素/窗口轮廓
  → 松手进入编辑态：标注、工具条、样式面板
  → 复制 / 保存 / 贴图 / OCR / 长截图 / 拼接 / 录屏
```

- 覆盖层是 `WS_EX_LAYERED` 分层窗口，按虚拟桌面坐标绘制，多屏不需要拼接 tile。
- 元素快照必须在覆盖层显示**之前**取（topmost 分层窗口会挡住 UIA 命中测试），
  遍历丢给后台线程，到位后 `PostMessage` 让覆盖层重画一次。悬停链是
  「元素 → 子窗口 → 顶层窗口 → 显示器」，滚轮换层级。详见 [`UIELEM.md`](UIELEM.md)。
- 标注保存为**数据**（图形列表），每次重绘重建；撤销/重做只操作列表，不存像素快照。
- 选区手柄支持越过对边翻转；拖动、缩放、键盘微调共用同一套命中测试。
- 标注选中后既拖控制点也拖**边线**改宽高（图形太小时只留控制点，否则中间没地方拖动整块）。
- 光标跟着「点下去会发生什么」走：选择工具箭头、文字工具工字、绘图工具十字，
  悬停已选中图形的边/角是缩放箭头、图形内部是四向箭头、工具条按钮是手型。
- 文字输入框浮在截图上，外框由外壳自绘三层（1px 深色 / 1px 白 / 2px 主题蓝）+ 白底
  EDIT：深色线跟白底分开、白线跟深底分开，纯白、纯黑、花背景都能看出输入区在哪。
  描边画在 EDIT 外面，EDIT 左上角仍落在点击点，提交后文字不会跳位置。

## 技术路线

- 抓屏：GDI `BitBlt` + `CAPTUREBLT`，覆盖分层窗口与硬件加速层；不引入 D3D11/DXGI。
- 绘制：`zx-ui::Canvas`（DIB + GDI+），文字/图标/圆角/阴影统一走设计 token。
- 长截图：不注入页面、不接管滚轮；按固定间隔抓同一区域，用行签名找滚动位移。
- OCR：装了 PaddleOCR 就优先走 `det.onnx` + `rec.onnx`（`ocr/` 目录），否则走 WinRT
  `SoftwareBitmap` → `OcrEngine::RecognizeAsync`；结果都按行/词回填。模型目录可自行放入后导入，
  下载源头（官方 / hf-mirror / 自定义）与进度都在设置页可见。
  - 结果窗口用原生多行 `EDIT` 承载正文：识别错字可以就地改、可以框选一段单独复制，
    复制按钮读的是输入框里的**当前内容**，不是原始识别结果。
  - 这个窗口不能是分层的（`UpdateLayeredWindow` 的窗口里子控件不参与合成），
    所以走普通窗口 + `SetWindowRgn` 圆角 + `WM_PAINT` 里 `BitBlt`。
- 贴图：无边框置顶窗口 + 自绘标题区，滚轮缩放、双击关闭。
- 录屏入口：选区交给 `record` 模块，覆盖层先销毁，避免被拍进帧。

## 文件与输出

```text
<截图目录>/截图_yyyyMMdd_HHmmss.png
```

- 默认保存目录可配置；文件已存在时自动加 `-2`、`-3` 后缀，不覆盖。
- 复制到剪贴板同时写 `PNG` 与 `CF_DIB`，兼容 Office、聊天工具与旧程序。

## 边界

- 受 DRM/安全桌面保护的窗口可能抓黑。
- 长截图依赖页面可滚动；固定表头/懒加载页面可能拼接错位。

## OCR 结果窗口

识别完弹一块可编辑的结果窗（原生多行 EDIT，能改、能框选、能只复制一段）。
顶部是标题和状态行，底部三个动作：

| 按钮 | 做什么 | 实现 |
| --- | --- | --- |
| 表格 | 拿原图重跑 det，按行列结构转成 **Markdown 表格** | 本地，`ppocr::table_markdown` |
| 翻译 | 按**当前选中的目标语言**翻译；旁边 `▾` 换语言 | 内置免费接口，可换成自己的 |
| AI 整理 | 让大模型修 OCR 的错字/断行/表格串行 | 用户自配 OpenAI 兼容接口 |

### 换行

EDIT 控件**只认 CRLF**：裸 `
` 会被吃掉，多行文本全挤成一行。写进控件前统一转换
（`ocr::crlf`）。行聚类也不再比"中心点差 10px"，而是**按垂直重叠**判定同一行——
字号一大就散、行距一紧就并，原来的做法两头都错。

### 表格识别的边界

靠"表格里的文字天然按列对齐"来切列，不是画线检测。设置页、报表、Excel 截图这类
规整表格够用；**合并单元格的复杂表会退化成空格子**。识别不出两行两列时明确告诉你
"不像表格"，不会拿一串串行的文字冒充表格。

### 翻译与 AI 的配置

都在设置页「截图工具 → OCR 翻译与 AI」里，落盘到 `settings.yaml` 的 `capture` 段：

```yaml
capture:
  # 留空 = 内置免费接口；填了就 POST {"text": "...", "to": "en"} 期待 {"text": "..."}
  translateUrl: ""
  # 目标语言：auto / zh / en / ja / ko / fr / de / es / ru
  translateTo: auto
  # 允许把正文发给**内置**第三方接口（有道 / Google）。默认 false，
  # 第一次点「翻译」会弹一次确认。填了自建 translateUrl 就不需要它。
  translateConsent: true
  aiBaseUrl: "https://api.openai.com/v1"
  aiModel: "gpt-4o-mini"
  aiPrompt: ""      # 可选，覆盖默认提示词
```

**AI Key 不在 settings.yaml 里**。它存在 `<exe>/imgbed/secrets.dat`，走 DPAPI 加密
（绑定当前 Windows 用户），和 settings.yaml 分开是因为那份文件经常被同步、备份、
贴进聊天。老版本写在 `aiKey` 里的明文 key 会在第一次使用时自动迁过去并清空原字段。

每一项右边有**测试**按钮，直接拿真实接口发一次请求告诉你通不通——免费接口说挂就挂
（有道的老端点 `fanyi.youdao.com/translate` 就已经返回空），不该让人靠"点了没反应"去猜。

命令行也能测：

```bash
zhuxia.exe --ocr-ai-probe translate
zhuxia.exe --ocr-ai-probe ai
```

### 内置翻译走哪个接口

按顺序试，第一个成功就返回（实测 2026-11-25）：

1. `aidemo.youdao.com/trans` —— 有道，国内直连、不需要 key，**当前可用**；
2. `translate.googleapis.com/translate_a/single?client=gtx` —— 国内多数不通，
   只给有代理的人兜底。

`fanyi.youdao.com/translate` 已经返回空响应，从候选里删掉了。

长文本按行切成 1000 字符的块分别翻再拼——GET 查询串太长会被服务端截断，而 OCR
结果动辄几千字。

### 目标语言：在结果窗口里选

翻译目标语言**不在设置里固定**，而是在结果窗口底部选：`翻译` 右边一个 `▾`，点开是
系统菜单（自动 / 中文 / 英文 / 日语 / 韩语 / 法语 / 德语 / 西班牙语 / 俄语），
**选完立刻翻**——点这个按钮的人就是要换语言重翻，让他再点一次「翻译」是多余的。

选定语言后按钮会变成 `翻译·英` 这样，一眼看得出当前目标。

设置里的 `translateTo` 只是**默认值**（默认 `auto`），决定窗口打开时预先选中的那一项。

`auto` 的语义：

* `auto` = 内容里有中日韩字符就译成**英文**，否则译成**中文**；
* 其余直接指定：`zh` / `en` / `ja` / `ko` / `fr` / `de` / `es` / `ru`。

**不用有道自己的 `to=Auto`**：那个在输入中文时译成英文、输入英文时译成中文，方向
不可控。用户选了目标语言就该按目标走。两家语言码不一样（有道 `zh-CHS`、Google
`zh-CN`），代码里统一成 `Lang` 枚举各自映射。

实测：

```text
translateTo: en   + "你好，世界"      → Hello, World
translateTo: auto + "你好，世界"      → Hello, World
translateTo: auto + "good morning"   → 早上好
```

### AI 的用途

定死是**清理 OCR 结果**，不是聊天。默认提示词要求它：修错字、按内容恢复换行与段落、
表格转 Markdown、代码保缩进，且只输出正文不加解释。OCR 输出的毛病正好是大模型最
擅长的活。没配 AI 时点「AI 整理」会直接告诉你缺哪几项。

## UI 元素识别## UI 元素识别

识别界面里的按钮/输入框/图标/文本区域，见 [`UIELEM.md`](UIELEM.md)。
主通道是 UIA（`Win32_UI_Accessibility`），OCR 负责文本。**视觉检测模型已决定不做**——
缺口只剩"自绘 UI 里没有文字的图标轮廓"，不值那个标注成本。
- 系统 OCR 的语言取决于已安装的语言包；装了 PaddleOCR 模型则不受系统语言包限制。
- 美化与标注在导出时栅格化；原始选区不保留。
