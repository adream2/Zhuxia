# 文档目录

这个目录**只放面向外部读者的文档**。判断标准是"一个第一次打开这个仓库的人，需不需要读它"，不是"作者写的时候有没有用"。

## 收录标准

一份文档进 `docs/`，必须**同时**满足三条：

1. **描述已发布的行为**——读者照着做能复现。不写"打算这么做"、不写"试过但删了"。
2. **对使用者或贡献者有用**——要么解释怎么用，要么解释代码为什么这样组织。
3. **不含过程性内容**——审计结论、踩坑记录、实测数据、方案对比、废弃设计，一律不收。

三条都满足才登记；只满足一两条的，放本地 `internal/`。

## 明确不收的内容

下面这些**曾经在 `docs/` 里，现在移到本地 `internal/`**，不随仓库分发：

| 类型 | 例子 | 为什么收在外 |
| --- | --- | --- |
| 代码审计报告 | `AUDIT-*.md` | 记录的是"当前有哪些弱点"，随修随变；公开只会变成过期材料，还会被当成产品现状 |
| 模块调研与踩坑 | `UIELEM.md`（含"采集踩过的五个坑""试过，零收益，已删"） | 是作者的推理过程，不是给读者的结论 |
| 设计稿 / 重构计划 | `UIELEM-REDESIGN.md` | 未落地的方案，读者没有可执行的动作 |
| 性能实测、对比实验、废弃 API | — | 数据会过期，且离开上下文容易被误读 |

`internal/` 已在 `.gitignore` 里整体忽略：文件留在磁盘上照常翻阅，只是不进版本库。

## 新增一份文档

两步，缺一不可（`docs/` 是白名单模式，忘了登记会直接提交不上去）：

1. 在 `.gitignore` 的文档区块里加一行 `!/docs/<文件名>.md`；
2. 在上面的「当前收录」表格里补一行，写清内容和主要读者。

拉取请求里如果只改了 `docs/` 却没动这两处，维护者应当要求补齐——**没有登记的文件不该存在**。

## 两个约定

- **图片一律用绝对地址**。README 与文档里的截图走官网（`https://zhuxia.ztsite.com/shots/…`），因为发布包里只有 `README.md` 与 `LICENSE` 等几个文件，相对路径在解压后的副本里必然失效。
- **内部资料不重写历史**。此前已经提交过的审计文档，只从当前版本移除，不改写 git 历史（改写会破坏已有标签与所有克隆）。它们不含密钥与本机路径，留在历史里没有安全影响。
